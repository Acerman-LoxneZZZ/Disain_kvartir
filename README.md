# Лендинг дизайнера интерьеров

Готовая адаптивная страница на React + TypeScript + Vite. Собранные статические файлы находятся в `dist/`. Все фотографии и шрифты размещаются локально; внешних запросов к фотобанку или Google Fonts при просмотре нет.

## Запуск

Требуется Node.js 22.12+ или 24 LTS.

```bash
npm ci
npm run dev
```

```bash
npm test
npm run build
npm run preview
```

`dist/` можно разместить на любом статическом хостинге. При размещении в корне домена дополнительные настройки маршрутизации не требуются.

## Замена контента

Откройте **`src/site.config.ts`** — это единый файл с именем дизайнера, биографией, контактами, проектами, услугами, этапами, FAQ, SEO и настройкой формы.

1. Замените `designer.name`, тексты, портрет и `contacts`. Пустые контакты не отображаются. Для телефона укажите международный номер в `phone`, красивую подпись — в `phoneLabel`. `telegram` — полный HTTPS-адрес.
2. Замените `projects`: название, тип, город, площадь, год, задачу, описание, состав работ и галерею. Сейчас всё это **демонстрационные примеры**, а фотографии не являются подтверждением авторства дизайнера. Для согласованной галереи загрузите реальные фотографии каждого проекта.
3. Изображения храните в `public/images/`. Для проектных изображений и первого экрана нужны варианты `имя-800.webp` и `имя-1600.webp`. В конфигурации проекта укажите базовый путь без суффикса: `/images/my-project`. Для портрета и сравнения укажите полный путь. Лучше сохранять пропорции исходного изображения, использовать качество WebP около 80–85 и ширину не более 1600–2000 px.
4. Пара «до / после» должна иметь один ракурс, одинаковые пропорции и совпадающую геометрию. Замените также её подпись: текущая честно сообщает об иллюстрации с помощью ИИ.
5. Укажите `seo.title`, `seo.description` и полный публичный `seo.url`. Метаданные HTML, `robots.txt` и `sitemap.xml` генерируются из конфигурации при сборке. После замены демонстрационного контента установите `demo: false`: подписи о демонстрации исчезнут, индексация будет разрешена.
6. Выполните `npm run build` и загрузите обновлённый `dist/`.

Вёрстка: `src/App.tsx`. Оформление: `src/styles.css`. Независимые интерактивные блоки: `src/components/`.

## Подключение заявок

По умолчанию `enquiry.endpoint` пуст. На странице есть явное сообщение, что заявки не отправляются; после заполнения формы ложное подтверждение не появляется.

1. Создайте серверный обработчик, например `POST /api/enquiries`, или используйте собственный HTTPS endpoint CRM/форм, совместимый с описанным ниже контрактом.
2. В `site.config.ts` укажите `enquiry.endpoint: '/api/enquiries'` либо полный HTTPS URL. Если URL внешний, сервер должен разрешать CORS для вашего домена и запрос `OPTIONS` с заголовком `Content-Type`.
3. Добавьте `enquiry.privacyUrl` — адрес действующей политики обработки персональных данных владельца сайта. Текст согласия в форме уже предусмотрен, но юридическую формулировку и законные основания обработки определяет владелец.
4. На сервере повторно проверяйте поля, ограничивайте частоту запросов, защищайте интеграцию от спама. API-ключи Telegram, почты и CRM храните **только на сервере**, не в конфигурации сайта.
5. Подтверждайте успех только после сохранения заявки или подтверждённой передачи в выбранную систему.

Тело запроса — JSON:

```json
{
  "name": "Имя клиента",
  "contact": "+7 999 123-45-67",
  "propertyType": "Квартира",
  "source": "interior-website"
}
```

Ответ при подтверждённом приёме: HTTP 2xx, `Content-Type: application/json`, **`{"ok":true}`**. Один HTTP 200 без `ok: true` не считается успехом. Ошибка: HTTP 4xx/5xx. По умолчанию ожидание — 15 секунд. При ошибке введённые значения остаются в форме; после подтверждённого успеха форма очищается. Данные не сохраняются в localStorage.

Проверяются имя, контакт (email, телефон 10–15 цифр, `@telegram` или `https://t.me/...`) и тип объекта. Неподключённый endpoint, сетевые ошибки, неподтверждённые ответы и таймауты покрыты тестами.

## Доступность и управление

- Галерея открывается в нативном `dialog`; Tab остаётся внутри, Escape закрывает, фокус возвращается на карточку. Стрелки влево/вправо переключают фотографии.
- Сравнение использует нативный range: мышь, касание, стрелки, Home/End. Видимый разделитель имеет соответствующее значение для скринридера.
- Мобильное меню управляется кнопкой с `aria-expanded`; Escape закрывает его.
- FAQ и услуги работают через нативные `details/summary`.
- Анимации отключаются при `prefers-reduced-motion`. Контент виден до срабатывания анимации.

## Материалы и публикация

Лицензии и источники: `ASSET-LICENSES.md`, `docs/image-provenance.json`, `docs/generated-image-prompts.md`. Нет вымышленных наград, отзывов или заявлений об опыте.

Сайт в Sites создан приватным для владельца. Для реального коммерческого запуска сначала замените демонстрационные материалы, подключите форму, настройте домен и индексацию, затем осознанно измените аудиторию сайта в настройках публикации.
